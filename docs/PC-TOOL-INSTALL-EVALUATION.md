# 能不能用爱思/iTools 那类 PC 工具装 App（2026-11-01 纸面论证）

## 结论

**现在不行，但缺的东西比想象中少。**

- 第一道关不是软件，是**物理通道**：我们内核里没有 USB gadget，
  设备插到电脑上只能充电（pandora 也一样，正在做 USB 串口）。
- 第二道关是**配对**：`lockdownd` 要建信任关系，这一步依赖 keybag/SEP，
  我们没有 SEP，必须桩掉。
- 好消息：**PC 工具要的那几个设备端服务，根镜像里都在**——
  `afcd`、`lockdownd`、`misagent`、`mobile_installation_proxy`、`installd`。
  只有 `usbmuxd` 在盘上没搜到（可能在共享缓存里，待上机确认）。

所以问题是"让它们跑起来 + 接上传输层"，不是"重写一套"。

## 一、这些通道分别是什么状态

| 组件 | 作用 | 盘上有没有 | 我们能不能跑 | 备注 |
| --- | --- | --- | --- | --- |
| USB gadget（设备侧） | 把设备枚举成 Apple 设备，承载 usbmux | ❌ 内核无 | 要写 | 最大缺口 |
| `usbmuxd` | 多路复用，PC 端所有服务的入口 | 盘上**没搜到**（可能共享缓存） | 未知 | 需要上机确认 |
| `lockdownd` | 配对、把服务挂出来（AFC / installation…） | ✅ `/usr/libexec/lockdownd` | 需启动 | 配对要 keybag |
| `afcd` | AFC 文件服务 | ✅ | 较容易 | 依赖 lockdownd 挂载 |
| `mobile_installation_proxy` | 安装 IPA 的服务入口 | ✅ | 较容易 | PC 工具走的就是它 |
| `installd` | 真正的安装执行者 | ✅ | 已在计划内 | 见 `INSTALLER-PLAN.md` |
| `misagent` | 装描述文件/签名配置 | ✅ | 可选 | 自签场景不一定需要 |
| keybag / SEP | 配对与信任的根 | ❌ 无 SEP | 必须桩 | 苹果工具会验证证书链 |

## 二、PC 端工具能不能直接认到设备

**理论上能，前提是把上面那套都补齐。** 爱思/iTools 这类工具做的事情很标准：

```
电脑 --USB--> usbmuxd --lockdown--> 取设备信息 / 挂 AFC / 调 installation_proxy
```

它们**不关心设备是不是真 iPhone**，只关心协议。所以只要：

1. 设备被枚举成 Apple 设备（USB 描述符对）
2. `usbmuxd` 在
3. `lockdownd` 能完成配对（Pair 请求返回正确的证书/记录）
4. 服务能挂出来

工具就会认。**卡点在 3**：配对记录是密钥学关系，苹果的 keybag 在 SEP 里，
我们只能给一个"永远接受"的桩，这会让苹果自己的工具在验证阶段出问题
（它可能校验设备证书）。**更稳的是自己写一个瘦客户端**，只讲
usbmux + lockdown + AFC + installation 四个协议，不做证书校验。

## 三、和 k60install 那条路线怎么组合

| 路线 | 内容 | 优点 | 缺点 | 优先级 |
| --- | --- | --- | --- | --- |
| **A. 纯设备端（k60install）** | 不碰 USB，设备上自己装 | 最快能出结果，现在就能写 | 每次装东西要先进设备（终端/串口） | **先做** |
| **B. 设备端苹果服务 + 自写 PC 客户端** | 让 lockdownd/afcd 起来，PC 端写瘦客户端 | 体验接近爱思，可批量 | 需要 USB 传输层 | 次做 |
| **C. 完整 USB gadget + 现成 PC 工具** | 走苹果原生协议，用爱思直接装 | 最省事（一旦通了） | USB gadget 是大工程，配对还卡 SEP | 最后 |

**建议组合**：

1. 先把 A 跑通（`k60install` + `uicache`），拿到"能装、能起图标、能启动"。
2. 再补传输层：不一定要完整 USB，先看能不能用 USB 串口（pandora 正在做）
   或网络回环把文件送进去，然后调 A 的安装器。
3. 最后才考虑 C。到那一步，`lockdownd` 的配对桩是绕不过的坎。

## 四、缺件清单

**必需（不做就用不了）**

- [ ] 内核 USB gadget（或替代传输：串口/网络）
- [ ] `usbmuxd` 是否存在（上机确认）
- [ ] `lockdownd` 配对桩（跳过 keybag/SEP）
- [ ] `afcd` 挂出来（AFC 服务）
- [ ] `mobile_installation_proxy` 可用（或直接调 `installd`）

**可选（体验更好）**

- [ ] `misagent`（描述文件）
- [ ] 设备证书伪装（让苹果工具信任设备）
- [ ] PC 端瘦客户端（自写）

## 五、工作量

| 项 | 估时 | 依赖 |
| --- | --- | --- |
| A 路线（设备内安装器） | 1–2 周 | 无（可离线写） |
| 传输层（串口或 USB 子集） | 3–5 周 | 设备 |
| lockdownd 配对桩 | 1–2 周 | 传输层 |
| 自写 PC 客户端 | 2–3 周 | 上面两项 |
| 完整 USB gadget + 兼容爱思 | 2–3 月 | 全部 |

## 六、一句话

**爱思那条路最终能走通，但它排在最后。** 现在最快的"装进去"仍然是
设备内的 `k60install`；PC 工具的价值在于批量与体验，等传输层和配对桩到位再谈。
